# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

php-src is the source code of the PHP interpreter. It is implemented in C11 and uses autotools for its build system.

## Build Commands

```bash
# Generate configure script (needed after modifying .m4 files or configure.ac)
./buildconf

# Configure for development (debug + thread safety)
./configure --enable-debug --enable-zts

# Configure with specific extensions
./configure --enable-debug --enable-opcache --enable-zts --disable-all

# Build (use -j with nproc for parallel)
make -j$(nproc)

# Rebuild after C source changes (no need to re-run configure)
make -j$(nproc)
```

## Testing

Tests use the `.phpt` format and are run via `run-tests.php`.

```bash
# Run full test suite
make test

# Run tests in parallel
make TEST_PHP_ARGS=-j$(nproc) test

# Run a single test
sapi/cli/php run-tests.php ext/standard/tests/strings/strlen.phpt

# Run all tests in a directory
sapi/cli/php run-tests.php ext/standard/tests/strings/

# Run tests for a specific extension
sapi/cli/php run-tests.php ext/opcache/tests/
```

### PHPT Test File Format

Tests are `--SECTION--` delimited files:

```
--TEST--
Description of what is being tested
--INI--
optional.ini.setting=value
--FILE--
<?php
// Test code here
?>
--EXPECT--
Expected output
```

Other common sections: `--SKIPIF--` (conditional skip), `--EXPECTF--` (printf-style wildcards like `%s`, `%d`), `--EXTENSIONS--` (required extensions), `--CREDITS--` (deprecated, don't add to new tests).

## Architecture

### Core Layers

- **Zend/** - The Zend Engine: lexer, parser, compiler, VM, garbage collector, memory allocator. This is the language runtime. Key files: `zend_execute.c` (VM executor), `zend_compile.c` (compiler), `zend_vm_execute.h` (generated VM dispatch), `zend_hash.c` (HashTable implementation), `zend_alloc.c` (memory manager).
- **main/** - Binds extensions, SAPIs, and the engine together. Handles streams, INI parsing, SAPI abstraction, output buffering.
- **sapi/** - Server API modules (cli, cgi, fpm, apache2handler, phpdbg, embed, litespeed, fuzzer). Each SAPI is how PHP interfaces with a web server or runtime environment.
- **ext/** - Extensions providing PHP functions/classes. Each extension has its own directory with `config.m4` (unix build), source files, and a `tests/` subdirectory.
- **TSRM/** - Thread Safe Resource Manager. Provides thread-local storage for ZTS (Zend Thread Safety) builds.
- **Zend/Optimizer/** - The opcache optimizer passes (SSA, SCCP, DCE, CFG, etc.). Separate from ext/opcache which handles the shared memory caching.

### Extension Structure

Each extension in `ext/` typically contains:
- `config.m4` - Autoconf build configuration
- `php_extname.h` - Header with module entry
- `extname.c` - Main source with `PHP_FUNCTION()` implementations
- `extname.stub.php` - PHP stubs that generate `extname_arginfo.h` via `gen_stub.php`
- `tests/` - PHPT test files

### Generated Files

These files are generated and should be regenerated rather than manually edited:
- `Zend/zend_vm_execute.h`, `zend_vm_opcodes.c`, `zend_vm_opcodes.h` - Generated by `Zend/zend_vm_gen.php` from `Zend/zend_vm_def.h`
- `*_arginfo.h` files - Generated by `build/gen_stub.php` from `*.stub.php`
- `ext/date/lib/parse_date.c` - Generated by re2c
- `Zend/zend_language_parser.c` - Generated by bison from `zend_language_parser.y`
- `Zend/zend_language_scanner.c` - Generated by re2c from `zend_language_scanner.l`

### Memory Management

Use `emalloc()`/`efree()`/`estrdup()` for request-scoped memory (freed automatically at request end). Use `malloc()`/`free()` only when memory must survive across requests or is managed by third-party libraries. Use `pemalloc(persistent, size)` when persistence is conditional.

## Coding Conventions

- C11 standard, K&R brace style
- Tabs for indentation (1 tab = 4 spaces)
- Use `PHP_*` macros in extension code, `ZEND_*` macros in Zend engine code
- Function names: `php_modulename_function()` for external API, `static` for internal
- User-facing functions wrapped in `PHP_FUNCTION()` macro
- Use `/* */` comments only, not `//`
- String length should use the stored length property, not `strlen()`
- Never use `strncat()`
- Bug references in commits: `GH-NNNNNN` for GitHub issues, `#NNNNNN` for old bug tracker

## Key Build Flags

- `--enable-debug` - Debug mode with assertions and memory leak detection
- `--enable-zts` - Thread safety (Zend Thread Safety). Always test with this to ensure TSRM correctness.
- `--disable-all` - Disable all optional extensions for minimal builds
- `--enable-opcache` - Enable the opcode cache extension
- Extensions are enabled/disabled via `--enable-extname` or `--with-extname` (the latter for extensions requiring external libraries)

## Regenerating Stubs

When modifying a function's signature (parameters, return type):

```bash
# Regenerate arginfo for a specific extension
php build/gen_stub.php ext/extname/
```
